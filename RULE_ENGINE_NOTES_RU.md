# Rule Engine / security findings — поставка 0.2.0

Основа: последний присланный архив `dogfighterAD-main(2).zip`. Это полное дерево проекта с изменениями, а не набор заглушек правил. Локальный патч находится в `RULE_ENGINE.patch`; удалённый GitHub-репозиторий не изменялся.

## Реализовано

Офлайн `RuleEngine`, версионированный пакет `dogfighterad.core/1.0.0`, **80 идентификаторов правил**, структурированные findings/evidence/missingData, детерминированные fingerprints, JSON/HTML, команды `analyze` и `rules`, настраиваемые пороги и коды возврата. Правила отдельно сообщают `Present`, `Potential`, `NotDetected`, `NotVerified`, `NotApplicable`, `Error`.

Каталог: 29 проверок пользовательских/компьютерных учётных записей, 3 — привилегированных учётных записей с доказанной цепочкой членства, 8 — доменных/тонких парольных политик, 4 — доверий, 7 — ACL, 20 — параметров реестра GPO, 7 — назначения привилегий GPO, 1 — непустого GPP cpassword, 1 — расхождения версий GPO. Конкретные условия, поля и ограничения: `docs/RULES.md` и `docs/RULE_ENGINE.md`.

**Нет поля — нет угаданного значения.** Числовой ноль, `false` и пустой массив в типизированной модели не подставляются вместо наблюдения. Необходимые `ObservedFact` проверяются по типу, disposition, идентичности, происхождению, временному окну и конфликтам. При пропуске выводится `NotVerified` с указанием нужного поля. Неполный сбор не может превратиться в полный успешный анализ.

Расширен сборщик: новый `SecurityPolicyCollector` читает доменные парольные/lockout-параметры, MachineAccountQuota и PSO-конфигурации. ACL сохраняет факт полноты разбора и присутствия GUID-полей. Членства сохраняют границы наблюдённого перечисления. SYSVOL сохраняет исходный тип записи реестра, нормализует разрешённые DWORD из security template и пишет явный результат проверки GPP cpassword, включая `false` после успешного разбора. Значение cpassword не экспортируется и не расшифровывается.

Совместимость: snapshot schema остаётся 2. Новое nullable-поле `RegistryValueType` не сериализуется при null, что сохраняет канонический round-trip старых читаемых снимков. Старым снимкам не дорисовываются отсутствующие поля: связанные правила дадут `NotVerified`, нужен повторный сбор. Контракты `directory.acls`, `directory.memberships`, `gpo.sysvol` повышены до 3, 2 и 2. Новый `directory.security-policy` — версия 1.

## Использование

```powershell
# Сначала сборка/тесты на машине с .NET 10 SDK:
.\scripts\verify.ps1

# Каталог правил:
dotnet run --project src/DogfighterAD.Cli -c Release --no-build -- rules

# Анализ существующего снимка:
dotnet run --project src/DogfighterAD.Cli -c Release --no-build -- analyze --snapshot .\new.dogad --output .\findings.json

dotnet run --project src/DogfighterAD.Cli -c Release --no-build -- analyze --snapshot .\new.dogad --output .\findings.html --format html
```

Для собранного CLI те же команды начинаются с `dogfighter` или `dogfighter.exe`. `--policy samples/analysis-policy.json` задаёт явные организационные пороги, `--rule ID` выбирает правило (опция повторяемая). `--fail-on high` меняет порог кода завершения, но не скрывает результаты. По умолчанию возрастные правила используют момент завершения snapshot, а не сегодняшнюю дату; для другого времени есть `--as-of` с часовым поясом.

Коды `analyze`: 0 — полный анализ без findings выше порога, 1 — полный анализ с findings, 2 — неполный анализ, 64 — неверные параметры, 70 — ошибка/лимит, 130 — отмена. Статус 2 важнее наличия findings: недостающие данные не маскируются найденными проблемами.

## Существенные границы

`Present` подтверждает узкое условие конфигурации, не успешную эксплуатацию. ACL findings — кандидаты без расчёта effective access/DCSync; GPO findings — сохранённая конфигурация без расчёта RSoP. Непустой cpassword — признак секрета, а не доказательство его действительности. SPN, делегирование и возраст — контекстные сигналы. `adminCount` не используется как доказательство привилегии. PSO не подменяется доменной политикой и не объявляется результирующей политикой пользователя.

AD CS/ESC, RBCD, LAPS, сетевые проверки, live validation, полный forest attack graph, retest/diff и отчёты о патчах ОС не выданы за готовые функции. Внутри 80 правил нет фиктивных «проверок», которые просто возвращают успех для этих областей. Новые потребители IRule должны перейти с прежнего контракта возвращаемых Finding на RuleEvaluation.

## Статус проверки

Нельзя трактовать количество написанных тестовых сценариев как количество прошедших тестов. Фактические результаты локальных проверок перечислены в `VALIDATION_RULE_ENGINE.md`.
